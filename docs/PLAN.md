# Spotcheck UI: build plan and research

This project began as Ledger UI. Dated results below keep the old name where it was true at the time.

Working note, started 2026-11-01. Everything here is the current best answer, not a contract.
Each phase gets its own short plan when we start it, and later phases may move.

Inputs: [the brief](../reference/ledger-ui-claude-code-prompt.md) and
[the prototype](../reference/ledger-ui-prototype.html). Where this note and the brief disagree,
this note wins. Decisions are also logged in Praxis under the project id `ledger-ui`.

## What we're publishing

A public website with a live, documented catalogue of React components, plus a shadcn registry
served from the same site. People run one command and the component source lands in their
project. There is no npm package to publish or version.

**Positioning:** a React component kit with hard edges, real motion and 3D. Reviewing AI work is its
strongest set, not its whole identity: only 10 of the 61 components are in the AI group. Chat
building blocks alone are not the opening; see [Who else is out there](#who-else-is-out-there).

## How we work

- Phases set the order and the exit check. Detail gets planned when a phase starts.
- The site deploys from Phase 0, so every phase is judged on a real URL.
- Show the docs page for each phase before moving on.
- Git follows the Praxis workflow: branch, PR, squash-merge, and nothing is committed unasked.

## Architecture

### Framework: Next.js

Next.js App Router, statically generated. React with Vite was the alternative, but Next wins for
a site that has to be published and found:

- Every docs page is prerendered with no extra SEO setup.
- `public/r/*.json` is served as plain static files.
- Most people installing these components use Next, so building on it exposes server/client
  problems before they do.

The build stays static apart from one demo route that streams scripted text: no database, no
accounts and no model calls.

### Repo layout

One Next.js app at the root. The brief suggested `apps/docs`, but there is only one thing to
deploy and no package to publish, so a monorepo adds setup and no benefit.

```
app/                      routes: /, /components/[slug], /docs/*, /roadmap, /compare, /support
components/site/          the site frame (nav, footer, previews); never installed by users
content/components/       one MDX file per component
content/docs/             install, tokens, skins, shadcn interop
registry/spotcheck/
  base/                   tokens, skins, shared utilities (ledger.css)
  components/spotcheck/   every component, one file each
  hooks/
  examples/               the demos on the site
public/r/                 generated by shadcn build, one flat folder
reference/                brief and prototype
scripts/                  registry build, clean-app install test
tests/                    unit and Playwright tests
registry.json             source; {{REGISTRY_URL}} is filled in per build
```

The nested `components/spotcheck/` path is deliberate. The CLI rewrites imports based on that path,
and components install to `components/spotcheck/` in the user's project, so they can't overwrite
shadcn files such as `components/ui/button.tsx`. Groups like Motion and Depth are set through
`categories` in `registry.json` rather than folders.

### How the pieces connect

1. Each component is one file in `registry/spotcheck/` and one entry in `registry.json`.
2. `shadcn build` writes `public/r/<name>.json`, and Vercel serves it.
3. Users run `npx shadcn add https://<site>/r/<name>.json`, or `@<namespace>/<name>` after
   directory approval.
4. Every component depends on the base item, which brings tokens, keyframes and fonts.
5. A site page imports the same source file for its demo, so the docs show exactly what installs.

### Site

- **Routes:** landing page, `/components` index, one page per component, `/docs` guides,
  `/field-notes`, and static `/r/*.json`.
- **Component page:** demo, engine tag, description, install command, usage, props, keyboard,
  reduced-motion note.
- **Theme and skin:** a small inline script in `<head>` sets both before first paint, because
  static pages can't read them on the server. Pages stay free of hydration mismatches.
- **Performance:** engines load per page. WebGL demos load on demand and mount only while on
  screen, since the prototype ran 7 WebGL canvases on one page.
- **Search:** `command-palette` over a list built into the page: components, guides, and skin and
  theme switches. It matches titles and descriptions, not page bodies. Add a real index only if
  the site grows past what a list can handle.
- **Publishing extras:** OG image per component, sitemap, `llms.txt`, privacy-friendly analytics.

### Rules for every component

- One file with constants at the top, and only the engine it lists.
- Flat named exports (`TabsList`, not `Tabs.List`), because dot access fails across the Next
  server/client boundary.
- Function props such as `render` need a client wrapper, and the docs must show it.
- `useId` for every id.
- No hard-coded colours, including inside WebGL.
- Under reduced motion: no animation, and WebGL renders one frame **per state change**, not one
  frame ever.
- Keep the brief's other non-negotiables on accessibility, WebGL lifecycle, mobile and data.

## Phase 0 results

- **Proved:** roll-number, detent-slider and bar-terrain install over HTTP into a brand-new
  shadcn app, build, and render correctly. Checked in a real browser: all three ways of switching
  to dark, condensed Archivo loading, no console errors, and shadcn's `--accent` left unchanged.
- **Public install:** the same 15 checks pass installing from
  `https://ledger-ui-pied.vercel.app`, a temporary address until the name is settled. Run them with
  `SPOTCHECK_REGISTRY_URL=<site> pnpm test:install`.
- **Name clash:** the variable can't be called `REGISTRY_URL`, because the shadcn CLI reads that
  name for its own default registry.
- **Hosting:** the GitHub repo is private and the Vercel production deployment is public. The
  Vercel project is linked to the repo, so pushes to `main` deploy.
- **Bundle cost, gzipped:** three.js with R3F is about 237 KB and Motion about 52 KB. Both load
  only on pages that use them, so no demo needs to change. Archivo's Latin file is 88 KB.
- **Tooling held back:** TypeScript 5.9 and ESLint 9 are pinned rather than TypeScript 7 and
  ESLint 10, which weren't tried.
- **Known noise:** three 0.187 logs a `THREE.Clock` deprecation warning that comes from R3F, not
  our code. It's a warning, not an error.
- **Learned about tokens:**
  - Everything is named so it can't collide with shadcn, including `--accent-ink` for the accent.
  - Tokens stay light unless the page opts in with `.dark` or `data-theme`, so a shadcn app with
    no theme provider never ends up half dark. The site opts in with `data-theme="system"`.
  - Tailwind compiles `light-dark()` to a fallback fixed on the declaring element, so every scope
    re-declares the tokens. Only a browser test catches this; a build passes either way.
  - The CLI only writes `@theme inline` through `cssVars.theme`, so the build script moves that
    block there.

## Design language

From the brief, with changes marked.

- **Layout:** full-bleed grids, hard rules, text seated at the bottom of each cell, a narrow
  numbered rail, titles inside the grid.
- **Geometry:** `--rule: 2px`, no radius, hard offset shadows only (`4px 4px 0 var(--ink)`).
- **Type:** Archivo variable (width 62–125) for display and body; display uses `font-stretch:
  62%`, weight 800–900, uppercase, tight leading. IBM Plex Mono for labels, numbers and metadata
  at 10.5–12px uppercase with `.12em` tracking. Instrument Serif for Folio only. Tabular numbers
  wherever digits line up.
- **Skins:** Ledger (`#2433E0` / `#7E88FF`), Terminal (`#A3530A` / `#FFB020`, all mono), Folio
  (`#C1122C` / `#FF5468`, serif italic display, no uppercase).

## Research: shadcn CLI and registry

Checked 2026-11-01 against shadcn's docs and CLI source.

- CLI v4 shipped in March 2026 and is at 4.23.0.
- **Item types:** `registry:base`, `block`, `component`, `font`, `lib`, `hook`, `ui`, `page`,
  `file`, `style`, `theme`, `item`.
- **`registry:base`** ships a whole design system as one payload: components, dependencies, CSS
  variables, fonts and config.
- **`registry:font`** makes fonts installable. The provider is currently Google only, which
  covers all three of ours.
- **`css`** adds `@layer`, `@utility`, `@keyframes` and `@plugin` rules to the user's CSS, so
  keyframes and shared classes can travel with the base item.
- **`cssVars`** has `theme`, `light` and `dark` keys. The CLI writes light to `:root` and dark to
  `.dark`, so tokens must also respond to `.dark`, as well as `[data-theme]` and the system
  setting.
- **`registryDependencies`** accepts bare names, URLs, `@namespace/item`, `owner/repo/item` and
  local paths.
- **Namespaces** are set per project under `registries` in `components.json`.
- **Presets** pack colours, theme, icons, fonts and radius into a short code. Worth a look for a
  Ledger preset.

**Getting listed in the directory:** the index had 525 registries, and none was named ledger. To
be listed, the registry must be open source, public, valid against the schema and **flat**, with
`registry.json` and each item at the root. Add it to `apps/v4/registry/directory.json` in
`shadcn-ui/ui`, run `pnpm validate:registries`, and open a PR. `owner/repo/item` addresses work
without any listing.

## Prototype problems not to carry over

Found by running it, unless marked. The prototype is the visual spec only.

- No viewport meta tag, so phones render it at 980px. With one added, Ledger and Folio fit 390px,
  but Terminal's price and badge run 8–13px past the edge.
- ⌘K isn't wired up; only the button opens the palette.
- The heatmap adds 168 of the page's 387 tab stops.
- Neither tab set has arrow-key navigation or `aria-controls`.
- The drum picker swallows the mouse wheel even on its last item.
- The drum and four canvases of about 300px use `touch-action: none`, which blocks page scroll on
  phones. Use `pan-y` with horizontal-only drag.
- Split-flap headers are misaligned (State at 320px, its column at 432px).
- Scramble text changes width between 172 and 214px while animating.
- Nine elements carry `aria-label` with no role.
- Mobile chat hides the thread list, and threads don't switch messages.
- From the code: `RM` is read once at load, the theme is polled every 40 frames, `pal()` depends
  on `.app`, and ids are hard-coded. Each breaks in a copied component.
- Use `example.com` rather than `northwind.in` in demo data.
